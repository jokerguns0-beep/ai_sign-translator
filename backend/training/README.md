# Обучение собственной модели РЖЯ (взамен / в дополнение к Gemini)

Это заготовка для второго этапа проекта: своя модель, обученная именно на
русском жестовом языке, вместо (или в дополнение к) обращению к Gemini.
Она не требует внешнего API, работает быстрее и может быть настроена
именно под нужный словарь жестов — но требует собственного датасета.

## 1. Формат датасета

Один пример = одна последовательность landmark-кадров + метка (слово/фраза).
Файл `dataset.jsonl`, одна запись на строку:

```json
{"label": "привет", "language": "rsl", "frames": [{"timestamp_ms": 0, "hands": [...], "pose": [...]}, ...]}
```

Структура `frames` — это список объектов `FrameLandmarks`, то есть ровно то,
что уже возвращает `LandmarkDetector.detect()` (см.
`backend/models/schemas.py`). Это специально сделано так, чтобы одни и те
же классы, что работают в проде, использовались и при сборе датасета —
никакого рассинхрона форматов.

Рекомендуемый объём: минимум 50-100 примеров на каждое слово/жест, от
разных людей, в разном освещении и с разных ракурсов камеры — иначе
модель выучит не жест, а конкретного человека и его комнату.

## 2. Сбор датасета

`collect_dataset.py` — интерактивный скрипт: включает камеру, ты
показываешь жест по команде, он записывает последовательность landmark в
`dataset.jsonl`.

```powershell
python -m training.collect_dataset --label привет --sessions 20
```

Это добавит 20 записанных повторов жеста "привет" в датасет. Повтори для
каждого жеста в твоём словаре, в идеале — с разными людьми перед камерой.

## 3. Обучение

`train_model.py` — эталонный скрипт PyTorch: LSTM поверх
последовательности landmark-координат, классификация на N жестов.

```powershell
pip install torch --break-system-packages
python -m training.train_model --dataset dataset.jsonl --epochs 50
```

Сохранит чекпоинт в `training/artifacts/gesture_model.pt` и `label_map.json`
(соответствие индекс класса → слово).

## 4. Экспорт в ONNX

Для быстрого продакшен-инференса без зависимости от PyTorch в рантайме:

```powershell
python -m training.export_onnx --checkpoint training/artifacts/gesture_model.pt
```

Создаст `training/artifacts/gesture_model.onnx` — именно этот файл ожидает
`services/local_model_backend.py`.

## 5. Подключение обученной модели вместо Gemini

В `services/translator.py` замени:

```python
self._recognizer = GestureRecognizer()
```

на:

```python
from services.local_model_backend import LocalModelBackend
self._recognizer = GestureRecognizer(backend=LocalModelBackend())
```

Всё остальное — буфер, WebSocket, фронтенд — не меняется вообще, поскольку
`LocalModelBackend` реализует тот же интерфейс `RecognitionBackend`, что и
`GeminiClient` (см. `services/recognition_backend.py`).

## 6. Реалистичные ожидания по точности

- На небольшом словаре (10-30 чётких, непохожих друг на друга жестов) и
  качественном датасете — точность 90%+ на новых людях вполне достижима.
- Чем больше словарь и чем более похожи жесты между собой (мелкая
  моторика пальцев, тонкие различия) — тем ниже точность и тем больше
  данных нужно.
- 100% точности не бывает ни у одной системы распознавания жестового
  языка, включая коммерческие продукты — всегда есть смазанные кадры,
  нестандартная жестикуляция конкретного человека, плохое освещение.
- Практичный путь: держать и Gemini, и локальную модель одновременно
  (ансамбль/фолбэк) — если локальная модель уверена, доверять ей (она
  быстрее и специализирована), если нет — подстраховываться Gemini.
